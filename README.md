# Intra Copilot

흩어진 정보를 지식으로 만들고, 연결하고, 다시 활용하는 Obsidian 지식관리 플러그인입니다. **챗봇·커넥터·제너레이터·리마인더** 네 가지 기능을 한 플러그인에 담았습니다.

> **노트 내용은 설정에 입력한 LLM 서버(챗봇)와 임베딩 서버(커넥터) 외에는 어디로도 나가지 않습니다.** 데스크톱 Obsidian 전용이며, 외부 인터넷 접속이 제한된 사내 환경에서도 쓸 수 있고, 사내 서버 또는 개인 로컬 환경의 AI 모델을 활용할 수 있습니다.
>
> 이 README는 한국어로 작성되어 있습니다. 영어 버전은 필요할 때 나중에 추가할 예정입니다.

## 기능

| 기능 | 상태 | 하는 일 |
| --- | --- | --- |
| **챗봇** | 사용 가능 | AI와 대화하며 노트를 작성·편집하고, 제안된 변경 사항을 검토한 뒤 반영 |
| **커넥터** | 사용 가능 | 연관된 지식 노트를 찾아 서로 링크하도록 추천 |
| **제너레이터** | 사용 가능 | 문서·메일의 텍스트를 정해진 양식에 맞춰 새 노트로 쓰기 |
| **리마인더** | 사용 가능 | 오래 다시 보지 않은 지식 노트를 하루 몇 개씩 다시 보여 주기 |

설정 처음 화면에서 **기능별 설정 카드**를 눌러 각 기능의 설정으로 들어갑니다.

## 챗봇

**묻기** — 사내 LLM(OpenAI 호환 API, 예: vLLM)에게 질문하고 답변을 받습니다. 답변은 글자가 차례로 나타납니다.

**노트를 읽히고 묻기** — 지금 보고 있는 노트가 입력칸 위에 칩으로 자동으로 올라옵니다. `@`로 다른 폴더·노트를 더 얹어 함께 읽힐 수도 있습니다. **칩에 올라온 것만 전송됩니다.**

**노트 고치기 (승인형 Diff)** — 챗봇이 노트를 고치자고 하면, **고치려는 근거**와 변경 전(빨강)/후(초록)를 보여주는 카드가 나옵니다. **[적용]을 눌러야** 노트에 반영되고, 누르기 전에는 아무것도 바뀌지 않습니다.

```
┌ 회의록.md                           [↗] ┐
│ 💬 회의 본문에 김영수 님이 맡기로 한      │
│    내용이 있어 담당자 줄에 반영합니다.     │
│ - 담당자 미정                            │
│ + 담당자: 김영수                         │
│                            [적용]       │
└────────────────────────────────────────┘
```

고칠 수 있는 노트는 **질문을 보낸 시점에 열려 있던 노트 하나**뿐입니다. 여러 노트를 자료로 읽히더라도 바뀔 수 있는 파일은 항상 하나여서, 어느 노트가 고쳐지는지 헷갈릴 일이 없습니다. 되돌리기는 **고친 부분만** 원래대로 돌리고, 적용 직전 원본은 플러그인 폴더의 `backups/`에 보관됩니다. [적용]하면 노트 속성의 `updated`·`read`에 오늘 날짜를 적습니다.

**그 밖에**
- **스킬(`/`)** — 자주 쓰는 작업 지시를 `SKILL/` 폴더에 .md 파일로 저장해 두고 `/`로 불러 씁니다. 메모장으로 고치거나 동료와 파일로 나눌 수 있습니다.
- **대화 기록** — `conversations/`에 저장되고 [지난 대화]에서 다시 엽니다. 보낸 메시지를 고쳐 그 지점부터 다시 대화할 수도 있습니다.
- **안전장치** — 답변 속 링크는 열리지 않고, 외부 이미지는 불러오지 않으며, 답변 속 코드(`dataviewjs` 등)는 실행되지 않습니다.
- **한국어 / English** — 플러그인 화면 표시 언어를 전환할 수 있습니다(문서는 한국어만).

## 커넥터

지금 보고 있는 노트와 **뜻이 비슷한 노트**를 찾아 링크를 넣도록 추천합니다. 왼쪽 리본의 커넥터 아이콘(가로줄 사이의 사슬 고리)으로 오른쪽 사이드바에 엽니다.

- **임베딩 서버** — OpenAI 호환 `/embeddings` API면 됩니다. 사내 API, 직접 띄운 자체 서버(llama.cpp의 `llama-server --embeddings`, Ollama, vLLM 등), 클라우드 API 모두 **서버 주소·API 키·모델**만 넣으면 똑같이 동작합니다. 챗봇 LLM 서버와 따로 설정합니다.
- **색인** — 처음 한 번은 **[색인 만들기]**의 확인 창에서 보낼 양(노트·조각·예상 요청 수)과 서버를 확인하고 **[색인 시작]**을 눌러야 노트 제목·본문을 서버로 보냅니다. 그 뒤로는 **자동 갱신** 주기(기본: 마지막으로 고치고 15초 뒤, 첫 변경부터 10분·30분·1시간 뒤 모아 보내기, 끄기)에 따라 새로 만들었거나 바뀐 노트만 보내고, 끄면 커넥터 창의 [업데이트]로 직접 맞추며, 속성·이름·링크만 바뀐 노트는 다시 보내지 않습니다. 서버 주소·모델이나 고급 설정(노트당 벡터 수·문서 형식·조각 최대 글자 수·벡터 크기)을 바꾸면 자동 색인이 멈추고 다시 만들어야 합니다.
- **추천** — 비슷한 노트를 유사도 순으로 보여 주고, 이미 링크한 노트는 흐린 카드와 "링크됨" 배지로 구분하고 [링크 넣기]를 빼서 같은 링크가 두 번 들어가지 않게 합니다. [링크 넣기]를 눌러 커서 자리에 넣거나, 버튼을 끌어다 노트의 원하는 자리에 놓습니다. 비교 계산은 PC 안에서 합니다.
- 색인은 플러그인 폴더의 `connector-index.bin`에 저장됩니다. 제외 폴더·조각 크기·보여 줄 개수는 **설정 → Intra Copilot → 커넥터**에서 바꿉니다.

## 제너레이터

받은 문서·메일을 **내 양식의 새 노트**로 만듭니다. 왼쪽 리본의 제너레이터 아이콘(가로줄 사이의 칸 나뉜 양식)으로 오른쪽 사이드바에 엽니다.

- **텍스트 넣기** — 텍스트를 붙여넣거나, **[열린 문서에서 텍스트 가져오기]**(Word·Excel·PowerPoint에 열려 있는 문서와 Outlook에서 고른 메일 중에서 고르기) · **[파일에서 텍스트 가져오기]**(닫혀 있는 Word·Excel·PowerPoint 파일을 보이지 않게 열어 텍스트만 읽고 닫기)를 씁니다. 입력칸은 좁게 보이며 **[새 창에서 텍스트 보기]**로 크게 보고 고칩니다. 이미 텍스트가 있으면 덮어쓰지 않고 뒤에 이어서, 문서 여러 개를 모아 한 노트로 만들 수 있습니다.
- **PDF는 지원하지 않습니다** — 보안(DRM) 문서를 이 경로로 열면 글자가 깨져 나옵니다. PDF 뷰어에서 복사해 붙여넣으세요. 문서 가져오기는 PowerShell로 각 프로그램에 물어보는 방식이라 **Windows에서만** 됩니다.
- **양식** — 볼트 안의 평범한 노트(.md)입니다. 괄호 ( ) 안에 무엇을 채울지 적어 두면 모델이 그대로 채우며, 새로 배울 문법은 없습니다. 양식 맨 위 속성(`---` 사이)에 있는 키만 만든 노트에 남고, 비어 있는 `created`는 플러그인이 채웁니다. 폴더에 노트가 없으면 예시 양식(회의록)을 하나 만들어 둡니다.
- **[만들기]** — 이때 텍스트·양식·공통 지시문이 **챗봇과 같은 LLM 서버**로 전송되고, 모델이 지은 제목으로 새 노트를 저장한 뒤 바로 엽니다(열기는 설정에서 끌 수 있음). 미리보기 단계가 없으므로 되돌리기는 만들어진 노트를 지우는 것입니다.
- **가져온 원문은 저장하지 않습니다** — 입력칸에만 있고 Obsidian을 끄면 사라집니다. 양식 폴더·저장 폴더·공통 지시문은 **설정 → Intra Copilot → 제너레이터**에서 바꿉니다.

## 리마인더

한 번 써 두고 묻힌 지식 노트를 **하루 몇 개씩 다시 꺼내 보여 줍니다.** 왼쪽 리본의 리마인더 아이콘(가로줄 사이의 시계)으로 오른쪽 사이드바에 엽니다.

- **범위** — 이 플러그인이 설치된 **볼트 안의 노트만** 살펴봅니다. 다른 볼트나 볼트 밖 파일은 보지 않고, **아무것도 전송하지 않습니다.**
- **올라오는 노트** — 읽은 기록이 없는 노트나, 다시 볼 날(`review`)이 된 노트입니다. 들어오는 링크가 없거나 미룸 태그(`#someday`, `#todo`)가 붙은 노트가 앞에 오며, 하루 5개씩 보여 주고 [더 보기]로 더 볼 수 있습니다. 템플릿 폴더와 Excalidraw 그림은 자동으로 뺍니다.
- **버튼** — [나중에 ▾](설정한 세 기간 중 고르기, 처음 값 7·30·90일) · [챗봇으로 열기](노트를 열고 새 대화의 칩으로 올림) · [보관함] · [삭제](두 번 눌러 확정). [나중에]·[보관함]·[삭제]는 알림의 [되돌리기]로 취소할 수 있습니다([삭제]는 알림 시간이 지난 뒤 휴지통으로 보냄).
- **기록은 노트 속성에** — [나중에]는 `read`·`review`, [챗봇으로 열기]는 `read`, 챗봇 수정 [적용]은 `updated`·`read`에 오늘 날짜를 적고, `created`가 비어 있으면 파일 날짜로 채웁니다. 이름을 바꾸거나 옮겨도 날짜가 노트를 따라가며, 속성 이름은 설정에서 바꿀 수 있습니다.
- 하루 한 번 알림, 제외 폴더, 새 노트 유예 기간, 나중에 기간·하루 개수·되돌리기 알림 시간은 **설정 → Intra Copilot → 리마인더**에서 바꿉니다.

## 설치

1. [Releases](https://github.com/minseok-yang/Intra-Copilot/releases)에서 **`main.js`, `manifest.json`, `styles.css`** 세 파일을 내려받습니다.
2. 볼트의 아래 경로에 폴더를 만들고 세 파일을 넣습니다.

	```
	<내 볼트 폴더>/.obsidian/plugins/intra-copilot/
	```

3. Obsidian에서 **설정 → 커뮤니티 플러그인**을 열고 Intra Copilot을 켭니다. (커뮤니티 플러그인이 꺼져 있다면 먼저 켜야 합니다.)

> **업데이트할 때도 이 세 파일만 덮어쓰세요.** 폴더를 통째로 지우고 새로 넣으면 같은 폴더에 있는 대화 기록·스킬·노트 백업이 함께 사라집니다.

## 시작하기

1. **설정 → Intra Copilot → 챗봇 → LLM 연결**에서 **서버 주소**(보통 `/v1`로 끝남)를 입력합니다. 서버가 인증을 요구하면 API 키도 입력합니다.
2. **[모델 목록 불러오기]**로 모델을 불러와 하나를 고릅니다.
3. **[연결 확인]**으로 그 모델이 실제로 답하는지 확인합니다.
4. 왼쪽 리본의 **챗봇 아이콘**(가로줄 사이의 말풍선)으로 챗봇을 엽니다. 상태가 **연결됨**이면 준비된 것입니다.

자세한 사용법은 **설정 → Intra Copilot → [사용자 가이드]**에서 볼 수 있습니다.

## 무엇이 서버로 전송되나요

현재 버전 기준으로, 설정에 입력한 **LLM 서버**(챗봇·제너레이터)와 **임베딩 서버**(커넥터)로만 아래 내용이 전송됩니다.

**챗봇 → LLM 서버**
- 채팅에 쓴 글과 그 대화의 이전 메시지(개수 제한은 설정에서 조정)
- 시스템 프롬프트와 `/`로 고른 스킬의 지시문
- **입력칸 위에 칩으로 올라와 있는** 폴더·노트의 내용(글자 수 제한은 설정에서 조정)
- 연결 확인용 테스트 문장과 모델 목록 요청

**커넥터 → 임베딩 서버**
- **[색인 만들기] 확인 창에서 [색인 시작]을 누른 뒤**, 제외 폴더·템플릿 폴더 밖 노트의 제목과 본문(속성 제외), 이후 바뀐 노트의 제목과 본문
- 연결 확인용 테스트 문장과 모델 목록 요청

**제너레이터 → LLM 서버** (챗봇과 같은 서버)
- **[만들기]를 누를 때** 입력칸의 글(붙여넣은 글, 가져온 문서·메일의 본문), 고른 양식 노트의 내용, 공통 지시문
- 문서를 가져오는 것만으로는 전송되지 않습니다(글이 입력칸에 채워질 뿐입니다). 파일 자체를 올리지 않고, 프로그램이 읽어 준 글자만 씁니다.

칩에 없는 노트는 챗봇으로 전송되지 않습니다. **리마인더는 아무것도 전송하지 않습니다.** 사용 기록이나 통계를 수집해 보내는 기능은 없습니다. 새 기능이 추가되어 통신 대상이 늘어나면 이 내용을 먼저 고친 뒤 배포합니다.

# 개발

공식 [obsidian-sample-plugin](https://github.com/obsidianmd/obsidian-sample-plugin) 템플릿(0-BSD)을 기반으로 만들어졌습니다. 플러그인 id는 `intra-copilot`입니다.

## 환경 준비

1. [Node.js](https://nodejs.org/) 설치 (버전 18 이상 권장). `node --version`으로 확인합니다.
2. 저장소를 내려받은 뒤 의존성을 설치합니다.

	```
	npm install
	```

3. 개발 중에는 파일 변경을 감지해 자동으로 다시 빌드합니다.

	```
	npm run dev
	```

4. 배포용 빌드:

	```
	npm run build
	```

	빌드가 성공하면 `main.js`가 생성됩니다. 이 파일은 git에 커밋하지 않고(`.gitignore`에서 제외) GitHub Release에 첨부합니다.

## 코드 검사

```
npm run lint
```


커넥터 모듈(색인·조각 나누기·벡터 계산)과 제너레이터의 노트 만들기 규칙(제목 읽기·속성 정리)을 Obsidian 없이 확인합니다. `test/obsidian-mock.ts`가 Obsidian을, 테스트 안의 작은 HTTP 서버가 임베딩 서버를 대신합니다. 이 모듈들을 고친 뒤에는 꼭 돌려 보세요.

`src/llm/client.ts`의 `fetch` 경고 1개는 **의도된 것**입니다 — 답변 스트리밍은 `requestUrl`로 할 수 없어 그 부분만 `fetch`를 씁니다.

## 새 기능을 만들 때

1. `src/ui/settings/features.ts`에 기능 id·상태(`'available'`)와 리본 아이콘을 더합니다.
2. `src/ui/settings-tab.ts`의 `sectionsFor()`에 그 기능의 설정 섹션을 넣습니다(섹션 코드는 `src/ui/settings/`에).
3. `src/content/docs.ts` 사용자 가이드에 그 기능 쪽을 더합니다.
4. **통신 대상이 늘어나는 기능이면**(커넥터의 임베딩 서버 등) 가이드의 "무엇이 전송되나요", 라이선스의 "데이터 처리", 챗봇 LLM 연결 화면의 전송 안내 문구, 이 README를 먼저 고칩니다.

## 테스트용 설치

빌드된 세 파일을 볼트의 `<내 볼트>/.obsidian/plugins/intra-copilot/`에 복사하고 커뮤니티 플러그인에서 활성화합니다. 개발 중에는 이 폴더를 저장소 경로로 심볼릭 링크 해두면 매번 복사하지 않아도 됩니다.

## 새 버전 릴리즈하기

1. `manifest.json`의 `version`과 `minAppVersion`을 갱신합니다.
2. `versions.json`에 새 버전과 그에 대응하는 최소 Obsidian 버전을 추가합니다.
3. 커밋·푸시한 뒤 버전 번호로 태그를 올립니다(`v` 접두사 없이, 예: `git tag 1.0.1 && git push origin 1.0.1`). GitHub Actions가 빌드해서 `main.js`, `manifest.json`, `styles.css`가 첨부된 **초안(draft) 릴리즈**를 만듭니다.
4. 초안에 한국어 릴리즈 노트를 쓰고 공개합니다. 한 번 공개한 버전 번호(태그)는 다시 쓰지 않습니다.
5. 라이선스·정책 문서를 고쳤다면 "문서 정보·문의" 쪽의 개정일과 변경 이력도 갱신합니다.

> `npm version patch|minor|major`로 `manifest.json`, `package.json`, `versions.json` 갱신을 한 번에 처리할 수 있습니다.
