# Intra Copilot

사내 폐쇄망에서 쓰는 Obsidian 챗봇입니다. 사내 LLM 서버와 대화하고, 노트를 읽혀 묻고, 챗봇이 제안한 수정을 하나씩 확인한 뒤 노트에 반영합니다.

> **노트 내용은 설정에 입력한 LLM 서버 외에는 어디로도 나가지 않습니다.** 데스크톱 Obsidian 전용이며, 인터넷 연결 없이 사내 서버만으로 동작합니다.
>
> 이 README는 한국어로 작성되어 있습니다. 영어 버전은 필요할 때 나중에 추가할 예정입니다.

## 무엇을 할 수 있나요

**1. 묻기** — 사내 LLM(OpenAI 호환 API, 예: vLLM)에게 질문하고 답변을 받습니다. 답변은 글자가 차례로 나타납니다.

**2. 노트를 읽히고 묻기** — 지금 보고 있는 노트가 입력칸 위에 칩으로 자동으로 올라옵니다. `@`로 다른 폴더·노트를 더 얹어 함께 읽힐 수도 있습니다. **칩에 올라온 것만 전송됩니다.**

**3. 노트 고치기 (승인형 Diff)** — 챗봇이 노트를 고치자고 하면, **고치려는 근거**와 변경 전(빨강)/후(초록)를 보여주는 카드가 나옵니다. **[적용]을 눌러야** 노트에 반영되고, 누르기 전에는 아무것도 바뀌지 않습니다.

```
┌ 회의록.md                           [↗] ┐
│ 💬 회의 본문에 김영수 님이 맡기로 한      │
│    내용이 있어 담당자 줄에 반영합니다.     │
│ - 담당자 미정                            │
│ + 담당자: 김영수                         │
│                            [적용]       │
└────────────────────────────────────────┘
```

고칠 수 있는 노트는 **질문을 보낸 시점에 열려 있던 노트 하나**뿐입니다. 여러 노트를 자료로 읽히더라도 바뀔 수 있는 파일은 항상 하나여서, 어느 노트가 고쳐지는지 헷갈릴 일이 없습니다. 되돌리기는 **고친 부분만** 원래대로 돌려서 그 뒤에 직접 고친 다른 편집은 건드리지 않고, 적용 직전 원본은 플러그인 폴더의 `backups/`에 보관됩니다.

## 설치

1. [Releases](https://github.com/minseok-yang/Intra-Copilot/releases)에서 **`main.js`, `manifest.json`, `styles.css`** 세 파일을 내려받습니다.
2. 볼트의 아래 경로에 폴더를 만들고 세 파일을 넣습니다.

	```
	<내 볼트 폴더>/.obsidian/plugins/intra-copilot/
	```

3. Obsidian에서 **설정 → 커뮤니티 플러그인**을 열고 Intra Copilot을 켭니다. (커뮤니티 플러그인이 꺼져 있다면 먼저 켜야 합니다.)

> **업데이트할 때도 이 세 파일만 덮어쓰세요.** 폴더를 통째로 지우고 새로 넣으면 같은 폴더에 있는 대화 기록·스킬·노트 백업이 함께 사라집니다.

## 시작하기

1. **설정 → Intra Copilot → LLM 연결** 탭에서 **서버 주소**(보통 `/v1`로 끝남)를 입력합니다. 서버가 인증을 요구하면 API 키도 입력합니다.
2. **[연결 확인]**을 누르면 모델 목록을 불러옵니다. 쓸 모델을 고르면 실제로 답하는지까지 확인합니다.
3. 왼쪽 리본의 **봇 아이콘**으로 챗봇을 엽니다. 상태가 **연결됨**이면 준비된 것입니다.

자세한 사용법은 **설정 → Intra Copilot → 일반 → [사용자 가이드]**에서 볼 수 있습니다.

## 무엇이 서버로 전송되나요

설정에 입력한 LLM 서버 **한 곳**으로만, 아래 내용만 전송됩니다.

- 채팅에 쓴 글과 그 대화의 이전 메시지(개수 제한은 설정에서 조정)
- 기본 지시문(시스템 프롬프트)과 `/`로 고른 스킬의 지시문
- **입력칸 위에 칩으로 올라와 있는** 폴더·노트의 내용(글자 수 제한은 설정에서 조정)
- 연결 확인용 테스트 문장과 모델 목록 요청

칩에 없는 노트는 전송되지 않습니다. 사용 기록이나 통계를 수집해 보내는 기능은 없습니다. 자세한 내용은 설정의 **[라이선스 및 정책]**을 보세요.

## 그 밖의 기능

- **스킬(`/`)** — 자주 쓰는 작업 지시를 플러그인 폴더의 `SKILL/`에 .md 파일로 저장해 두고 `/`로 불러 씁니다. 텍스트 파일이라 메모장으로 고치거나 동료와 파일로 나눌 수 있습니다.
- **대화 기록** — 대화는 `conversations/`에 저장되고 [지난 대화]에서 다시 엽니다. 보낸 메시지를 고쳐서 그 지점부터 다시 대화할 수도 있습니다.
- **안전장치** — 답변 속 링크는 열리지 않고, 외부 이미지는 불러오지 않으며, 답변 속 코드(`dataviewjs` 등)는 다른 플러그인이 실행하지 못하게 막습니다.
- **한국어 / English** — 플러그인 화면 표시 언어를 설정에서 전환할 수 있습니다(문서는 한국어만).

# 개발

공식 [obsidian-sample-plugin](https://github.com/obsidianmd/obsidian-sample-plugin) 템플릿을 기반으로 만들어졌습니다. 플러그인 id는 `intra-copilot`입니다.

## 환경 준비

1. [Node.js](https://nodejs.org/) 설치 (버전 18 이상 권장). `node --version`으로 확인합니다.
2. 저장소를 내려받은 뒤 의존성을 설치합니다.

	```
	npm install
	```

3. 개발 중에는 파일 변경을 감지해 자동으로 다시 빌드합니다.

	```
	npm run dev
	```

4. 배포용 빌드:

	```
	npm run build
	```

	빌드가 성공하면 `main.js`가 생성됩니다. 이 파일은 git에 커밋하지 않고(`.gitignore`에서 제외) GitHub Release에 첨부합니다.

## 코드 검사

```
npm run lint
```

`src/llm/client.ts`의 `fetch` 경고 1개는 **의도된 것**입니다 — 답변 스트리밍은 `requestUrl`로 할 수 없어 그 부분만 `fetch`를 씁니다.

## 소스 구조

```
src/
  main.ts           플러그인 진입점(생명주기, 리본 아이콘, 뷰 등록)
  settings.ts       설정 데이터 정의와 기본값
  i18n.ts           화면 문구(한국어/영어, 두 언어의 키 구조를 타입으로 강제)
  plugin-paths.ts   플러그인 폴더 경로(대화 기록·스킬·백업 저장 위치의 기준)
  content/docs.ts   사용자 가이드·라이선스 문서 본문(마크다운 문자열, main.js에 번들)
  chat/             대화 저장, 칩에 올라온 볼트 자료 수집, 요청 조립, 답변 안전 처리,
                    수정 제안 파싱·대조·적용(승인형 Diff)과 적용 전 원본 백업
  skills/           스킬 파일 읽기·쓰기(SKILL 폴더)
  llm/              OpenAI 호환 API 호출, 연결 상태 보관
  ui/               설정 화면, 챗봇, 목록·입력 목록 등 화면 코드
```

반입 파일을 세 개(`main.js`, `manifest.json`, `styles.css`)로 유지하기 위해, 문서도 별도 파일이 아니라 `content/docs.ts`의 문자열로 두고 번들합니다.

## 테스트용 설치

빌드된 세 파일을 볼트의 `<내 볼트>/.obsidian/plugins/intra-copilot/`에 복사하고 커뮤니티 플러그인에서 활성화합니다. 개발 중에는 이 폴더를 저장소 경로로 심볼릭 링크 해두면 매번 복사하지 않아도 됩니다.

## 새 버전 릴리즈하기

1. `manifest.json`의 `version`과 `minAppVersion`을 갱신합니다.
2. `versions.json`에 새 버전과 그에 대응하는 최소 Obsidian 버전을 추가합니다.
3. GitHub에서 새 버전 번호로 Release를 생성하고(`v` 접두사 없이, 예: `1.0.1`), `main.js`, `manifest.json`, `styles.css`를 첨부합니다.
4. 릴리즈 노트는 한국어로 작성합니다.

> `npm version patch|minor|major`로 `manifest.json`, `package.json`, `versions.json` 갱신을 한 번에 처리할 수 있습니다.
